# 使用与迁移

[返回首页](../README.md)

## 配置

所有路径均按 **AB 容器内的视角**填写。下载器路径不同，用 `path_map` 转换；合集的读取路径不同，用 `collection_path_map` 转换，两者用途不同。

| 选项 | 用途 |
| --- | --- |
| `source_root` | AB 可读的下载根目录，默认 `/downloads` |
| `library_root` | AB 可写的视频库根目录，默认 `/library` |
| `tv_subdirectory` / `movie_subdirectory` | 默认 `Shows` / `Movies`；根目录已是对应媒体库时将该分类子目录留空 |
| `music_root` | 可选的独立音乐根目录；留空先归档，配置后可补整理 |
| `collections_root` | 可选的独立合集清单目录，须由 Jellyfin 单独扫描 |
| `path_map` | 下载器实例、远端前缀与 AB 本地前缀，字段为 `downloader`、`remote`、`local` |
| `collection_path_map` | AB 与清单读取方的路径前缀，字段为 `local`、`remote` |

输出根与下载根不能互相包含。目录须事先挂载；AB 的运行 UID/GID 需要读取下载、写入输出的权限，Jellyfin 需要读取输出的权限。插件不修改文件权限；同一磁盘卷不保证跨挂载能硬链接或 Reflink。

默认剧集模板为 `{title} S{season:02d}E{episode:02d}{version}`，电影模板为 `{base}{version}`。插件自动添加扩展名。`version` 包含分隔符和组名。同一剧集任务里有两个或更多不同的正片集号时，版本名另加「合集」。例如同组第 1 集可同时保存为 `示例 S01E01 - Group.mkv` 和 `示例 S01E01 - Group 合集.mkv`，各自的外挂字幕和音轨跟随对应视频。特典及同一集的多个编码不会单独触发合集识别。

自定义模板中的 `group` 只表示组名。要保留单集与合集两个版本，请启用版本后缀并在剧集模板中包含 `{version}`。关闭后缀后 `version` 为空。模板还支持 `year`、`tmdb_id` 和 `base`（作品名、年份与可选 TMDB ID）。

升级时，预览会列出按新模板改名的旧合集文件。自动整理开启时，下次扫描会核验并复用已有副本。若旧合集占用了新单集的目标名，旧合集改名后，下一轮扫描即可整理该单集。

## 单番设置

在「番剧详情 → 媒体库」中预览本番、确认未关联任务、设置 TMDB 纠错或任务级逐文件映射。优先级为任务覆盖 → 单番覆盖 → AB 元数据；季集默认继承 AB 的季度和偏移，纠错无需重复填写一套全局规则。

选定 TMDB 电影后，若正片候选只有一个，插件会直接使用它。候选较多时，插件读取文件名的角色标签。例如 `作品 - Main Feature.mkv` 配上 `作品 - 歌名 MV.mkv`，正片进入电影目录，MV 保留原名进入 `extras/`。只有一个候选明确标为正片、其余候选均标为附加视频时才会自动选择。遇到未标明用途的视频或多个剪辑版本，可以在「下载任务与逐文件设置 → 电影正片」指定文件。

选择「仅音乐与归档附件」后，手动及自动整理均不处理该番的视频、字幕和外挂音轨，也不改变其已有记录。移除 TMDB 覆盖会恢复跟随 AB，不会停用整理。

## 读懂预览

预览只核验，不改媒体文件。表格按文件显示源路径、已有副本、目标、操作和原因，可按番名、路径和操作过滤。**筛选只改变显示，执行仍应用完整计划。**

| 操作 | 确认后的行为 |
| --- | --- |
| 已有目标 · 不变 | 不处理媒体内容 |
| 复用已有副本 / 接管旧文件 · 改名 | 核验所有权或完整内容，在媒体库内移动已有副本 |
| 接管已有目标 | 登记已核验目标，不复制 |
| 新建目标 | 执行时尝试硬链接、Reflink、普通复制；结果显示实际方式 |
| 待确认 | 保留文件，按原因修正映射、权限或冲突后重新预览 |
| 已跳过 | 本次不整理，原因保留在表格中 |

计划有效期 15 分钟且只能执行一次。执行前重新核对配置、映射和文件状态；相关内容变化需重新预览。进度按文件数计算，历史记录保存源、目标、实际方式及最新状态。

## 接管旧媒体库

接管前备份 AB 的配置和数据。点击「接管整理」只停用原生整理；完整预览确认后才迁移文件。

插件先读取原生硬链布局及成功记录，必要时只在当前作品目录查找同扩展名、同大小的视频或关联字幕／音轨，再以文件身份或完整 SHA-256 核验。文件名、季集号和大小本身不足以证明版本相同。多个有效候选保持待确认，其他条目已拥有的目标不接管。

已验证 AB 4.0 的 `PnRename`、`AdvanceRename`、`TemplateRename` 和保留原名输出。无法从源文件恢复集号的任意模板仍需逐文件确认。首次大文件内容核验可能较慢，界面会显示进度。

旧副本在媒体库内原子移动，目标存在时不覆盖；无法安全移动则失败，保留原文件，不降级为重新复制。成功后清理旧文件父目录链中的空目录，遇到非空目录停止，保留配置根目录、下载目录及符号链接。已核验复用不改变旧副本原有的空间占用。

## 音乐目录已在外部移动

适用于已由文件管理器移动音乐、只需修正插件路径记录的情况。

1. 关闭自动整理，移动目录并调整挂载，在插件选项保存新的 `music_root`。
2. 展开「音乐目录已在外部移动」，填写**原 AB 容器内路径**，点击「预览路径记录更新」。
3. 原下载须仍可读取。插件逐文件比较原下载与新目标的完整 SHA-256；全部通过后，点击「仅更新路径记录」。
4. 插件再次核验并备份，整批更新目标身份、历史与合集引用。媒体文件不移动、改名或复制；自动整理保持关闭，重新完整预览后再开启。

根目录改变但记录尚未更新时，旧音乐保持待确认；权限或 I/O 错误不会被解释为缺失文件。

## 停用与恢复

关闭自动整理只停止后续扫描；手动整理仍可用。停用或卸载插件保留媒体文件，且不自动恢复原生重命名、硬链。需要恢复时，先停用本插件，核对原生目录和命名策略，再手动启用原生流程。

## 更新与数据

插件数据位于 `config/plugin-data/library-organizer/`，包括 `library.sqlite3`、`backups/` 和更新目录 `updates/<ID>/previous/`。备份可能含私人路径及配置，不要公开上传。

更新需要 AB 对插件目录及其父目录有写权限，更新暂存与插件目录须在同一文件系统。加载失败恢复旧代码，数据库不会自动用旧快照覆盖；备份不自动清理。断电等进程外中断时，先停止 AB，从 `previous/` 恢复旧代码，再按需恢复对应数据备份。

保留插件数据目录即可保留整理记录。备份 SQLite 时停止 AB 或使用在线备份，不要在运行时只复制主数据库而漏掉 WAL。

## 日志与站内通知

在 AB「日志」中查找 `plugin.library-organizer` 或 `audit`。每条包含时间、事件名及本次 `run` 编号；文件操作记录源、目标、实际方式、清理的路径和失败原因。API 日志只记录路由、条目 ID、结果和耗时，不记录请求体或预览凭证；URL 在插件操作日志中会被遮蔽。私人路径仍会保留，分享前请脱敏。

普通日志记录实际写入、失败与重试、数据库备份、合集更新和每六小时的版本检查。无变化的每分钟扫描、预览核验与缓存同步在 DEBUG 中逐次记录，普通日志每小时或状态变化时记录摘要。需要逐次跟踪时开启 AB 的调试日志；这些是业务操作记录，不是每次系统调用或 SQL 的审计。日志沿用 AB 的轮转与保留策略，整理历史仍保存在插件数据库。

新集通知显示在 AB 铃铛中，包含作品、季集号和目标文件名。只有视频已完成、目标校验通过并提交成功记录后才进入待发送队列；通知写入失败按分钟重试，媒体整理不回滚。已发送记录持久去重，不调用外部通知渠道。历史下载的首次接管、已有副本改名、字幕／音乐／附件和重复扫描不发新集通知；待确认或失败的文件也不发。缺少完成时间的下载器以首次完整扫描建立基线；之后发现的新完成任务才提醒。

「已入库」表示文件整理完成，Jellyfin 的扫描与识别仍由媒体服务器完成。
